# 对话、Agent 与后台任务

首次安装请先阅读[项目 README](../README.md)。本文说明运行行为与接口约定。

## 对话列表

`GET /api/assistant/conversations` 返回流萤、Codex 和 Claude 的会话。列表默认仅返回未归档会话，传入 `archived=true` 查看归档列表；`PATCH /api/assistant/conversations/:id` 的 `is_archived` 字段设置归档状态，排队或运行中的对话暂时不可归档。侧边栏对话可置顶或取消置顶，桌面端使用图钉按钮，移动端通过每条对话的更多操作菜单设置，状态保存在服务端。列表和搜索均在数据库中先过滤，再按 `is_pinned`、`last_message_at`、`id` 倒序分页：置顶对话优先，同组内最新对话在前；默认每页 20 条，`limit` 最大 100。将返回的 `next_cursor.before_pinned`、`next_cursor.before_at`、`next_cursor.before_id` 作为下一页查询参数；`next_cursor` 为 `null` 时已到末尾。`search` 支持标题、工作目录、来源目录和 Agent。`PATCH /api/assistant/conversations/{id}` 接受 `title` 或 `is_pinned`，仅能修改自己的对话。改变置顶状态会更新 `updated_at`，重复设置同一状态不会延长保留期；置顶对话同样遵循 CONVERSATION_RETENTION_DAYS 配置的清理规则。

`selected_id` 可单独读取当前选中的会话，结果放在 `selected_conversation`，不受当前页或搜索条件限制，并校验用户归属。前端实时刷新会更新已加载的分页，保留旧会话的访问和搜索能力。

新对话可选择流萤、Codex 或 Claude，首次发送时创建会话；后续消息追加到同一会话。同一会话顺序执行，不同会话按并发额度执行。切换会话不会停止后台任务，返回或刷新后恢复生成。流萤通过更多功能入口访问定时任务和已启用的模块页面，模型可调用已分配的工具。

并行模式在独立副本中执行，Git 已跟踪文件还原到准备开始时的提交，未跟踪和忽略文件保留可复制的内容。来源目录可同时运行编译或清理任务：扫描或打开前已消失的普通文件、目录会跳过；打开后被删除的文件仍通过文件句柄复制。来源根目录或 Git 元数据消失、仓库提交变化、权限或磁盘错误仍会中止准备并清理临时副本。普通文件的复制不是整个目录同一时刻的快照。

启用带页面的模块后，对话右上角的更多功能菜单会显示清单声明的入口。模块页面支持关闭按钮、Esc 和点击遮罩关闭。侧边栏左下角仅显示设置图标，点击后向上展开“Agent 配置”“扩展模块”和“退出登录”，平时隐藏这三项操作。移动端对话以紧凑的创建目录文字前缀和单行标题显示，目录前缀不带图标或分隔线。

仓库中的重要日期示例提供日期列表、配置和自动检查，启用后从更多功能菜单打开模块页面。示例代码及安装方式见 [模块文档](modules.md)。

新对话入口位于对话标题栏，只显示图标；移动端放在展开侧边栏按钮右侧，侧边栏和桌面收起导航不再保留重复入口。

Codex 对话标题栏提供“模型设置”，运行或排队时也可修改 API 平台、模型和推理级别。保存后提交的新消息使用新设置，已运行或已排队的消息保留提交时的配置；任务配置持久化，重试和服务重启恢复也沿用原设置。保留会话 ID、历史和工作目录，刷新或服务重启后仍使用保存的设置。归档对话需先取消归档。平台须已在服务账号的 Codex 配置中配置；模型及推理级别沿用新对话的选择规则，模型目录不可用时可手动输入。`PATCH /api/assistant/conversations/{id}/codex-settings` 使用 `provider`、`model`、`reasoning_level` 整体替换三项设置，空值恢复配置默认；`provider: "openai"` 明确选择官方平台。保存与消息提交使用同一数据库写锁，每条 Codex 消息在提交时保存三项配置快照，保存设置不会中断正在执行的任务。底层配置变化时仅卸载并恢复对应的空闲 Codex 线程，核对平台与模型后才开始下一轮，不重启其他对话使用的连接。

旧流萤记录作为各自独立的会话显示，不合并历史。旧引用分支继续使用保存的祖先上下文，消息接口的 `source_reply` 返回来源回复预览和可用的会话 ID；原会话删除后仍保留预览与继承上下文。旧 `/api/assistant/firefly/messages` 接口及实时订阅暂时保留，供升级前的客户端兼容使用。

Claude 在新建对话、现有对话标题栏和定时任务中提供 API 平台、模型和推理级别选择。默认平台 `cli` 读取服务运行账户的 `~/.claude/settings.json`，并沿用 Claude CLI 登录和环境；设置了 Claude 原生的 `CLAUDE_CONFIG_DIR` 时，配置目录随之改变。`CLAUDE_MODEL`、`CLAUDE_MODELS` 仅保留为旧部署的可选覆盖，不需要再在 `.env` 登记平台列表或默认推理级别。

额外平台放在 `<Claude 配置目录>/providers/*.json`，文件名就是平台标识，例如 `providers/relay.json` 对应 `relay`。**这个目录的发现规则由 Firefly 约定，文件内容使用 Claude 原生 settings 格式**，也可以直接用 `claude --settings ~/.claude/providers/relay.json` 运行。`cli` 是保留标识。配置按次读取，新增、修改和删除文件无需重启 Firefly；个别文件无效时返回具名提示，其他平台仍可选择。

每个平台文件使用原生 `env.ANTHROPIC_BASE_URL` 指定 Anthropic Messages API 地址，或使用原生 Bedrock、Vertex、Foundry 开关；使用 `model` / `env.ANTHROPIC_MODEL` 设置默认模型，`availableModels` 及模型别名环境变量提供候选模型。`availableModels` 同时是 Claude 原生模型白名单，手动选择也受其约束；不需要限制模型时可省略该字段。平台对应的 Opus、Sonnet、Haiku、Fable 和子 agent 模型映射也在同一个原生文件中管理。示例见 [`examples/claude/providers/gateway.json`](../examples/claude/providers/gateway.json)。复制到用户配置目录后，将示例地址、模型和凭据来源替换为实际配置；凭据文件保持仅当前用户可读，不提交仓库。

凭据采用原生 `env.ANTHROPIC_API_KEY`、`env.ANTHROPIC_AUTH_TOKEN` 或 `apiKeyHelper`。例如 `"apiKeyHelper": "printenv EXAMPLE_CLAUDE_API_KEY"` 可以复用现有密钥环境变量，无需复制密钥值；也支持原生凭据脚本。平台列表接口不运行凭据助手，仅 Claude 执行本轮请求时按原生机制调用。前端只收到平台名、地址、模型和默认推理级别，原始 `env`、密钥、凭据助手和其他私有设置不会返回浏览器。

默认推理级别读取原生 `env.CLAUDE_CODE_EFFORT_LEVEL` / `effortLevel`，界面提供默认、`low`、`medium`、`high`、`xhigh`、`max`，具体可用档位由模型和平台决定。选定平台后，将其原生 settings 与本轮选择合并为私有临时配置，并通过 `--settings`、`--model`、`--effort` 启动 Claude；平台文件中的权限、模型映射等原生配置保留。覆盖本轮的平台路由和认证变量，防止继承其他平台的凭据，不修改全局 settings 或服务器环境。临时配置随本轮回收；空模型仍显式选择该平台当前默认模型，避免恢复会话时沿用之前的模型覆盖。

`GET /api/assistant/claude/models` 返回平台列表、默认平台、各平台候选模型和推理选项。创建 Claude 对话使用 `provider`、`model`、`reasoning_level`；现有对话通过 `PATCH /api/assistant/conversations/{id}/claude-settings` 整体替换三项，例如 `{"provider":"relay","model":"opus","reasoning_level":"high"}`，空值恢复服务默认。保存与消息提交使用同一数据库写锁，每条消息保存三项配置快照；修改只影响之后提交的消息，重试和重启恢复继续使用原快照。会话 ID、历史和工作目录保留。运行和排队时可以保存，归档对话须先取消归档。

## 对话消息重试

`POST /api/assistant/conversations/{id}/messages` 和兼容的 `/api/assistant/chat` 接口接受 `Idempotency-Key: <UUID>` 请求头。前端每次新发送生成一个 ID，失败重试沿用该 ID。请求身份按用户与会话隔离，数据库事务保证并发重试只创建一条消息和一个任务；成功或失败的任务再次提交会返回原任务，不重复执行。

同一 ID 的消息文本（去除首尾空白后）、工具开关、附件名称、类型、顺序和内容须保持一致，否则返回 409；附件上传时计算 SHA-256，重复上传的临时副本会清理。用户删除排队消息后，该 ID 会保留删除记录，重试返回 409；重新发送须使用新的 ID。未提供请求头的旧客户端保持原有行为，不保证提交去重。会话删除时同步删除请求身份记录。新增数据库迁移由启动自动执行，升级前按 [README](../README.md) 备份。

## Agent 执行、恢复与预算

所有 Agent 共用并发额度（`ASSISTANT_MAX_CONCURRENT_JOBS=4`）和等待队列上限（`ASSISTANT_MAX_QUEUED_JOBS=32`）。达到额度时任务保持排队；等待队列满时新提交返回 429 和 `Retry-After: 5`，相同请求 ID 的重试仍返回原任务。取消请求先持久化取消意图，worker 等执行及清理结束、终态成功写库后才释放会话；终态写入失败持续退避重试，修复数据库可恢复推进，无需重复执行任务。

SSE 使用执行版本 `execution_id` 和版本内序号 `seq`。服务重启、任务重新执行、事件记录过期或流接口已清理时，浏览器恢复该任务的完整持久化快照，短期轮询至任务结束。流式缓存每任务最多 10000 条及 4 MiB，终态保留 60 秒；缓存失效不会拼接来自不同执行的回复片段。

每轮回复在消息区只展示最新一条 Agent 文字回复，较早的中间说明自动归入执行过程；流式更新、任务完成和历史重载均采用同一规则。图表、生图等结果保持可见。执行过程、工具调用和任务详情默认收起，用户展开后保留其选择。展开过程块只读取步骤名称与状态，点击单个工具后通过有会话权限校验的详情接口加载输入输出；运行中的详情仅在展开时刷新。模型仍读取完整工具结果。主 Agent 与所有子 Agent 均不设模型轮数上限，取消与超时继续生效。

最新回复使用同轮内稳定的外层容器，单条消息的 Markdown 节点继续独立更新。自动跟随底部时，长回复替换为短回复会临时保留原占位并将新内容底部对齐，避免内容高度骤减引起回跳；任务结束时保留阅读位置。用户主动向上滚动、点击回到底部或下一轮回复出现时回收占位，并补偿可见内容的位置。占位仅存在于当前页面，不修改消息记录。

“执行了多久”按整轮任务的实际开始与结束时间计算，排队等待不计入，工具结束后继续计入模型生成回复的时间。同轮包含多个过程块时，仅最后一个显示整轮耗时和运行效果；前面的块显示“执行过程”，仍可展开查看详情。起止时间持久化，服务重启续跑保留最初开始时间；流式重放使用事件原始发生时间。旧记录没有准确起止时间时，按已有过程记录至最终回复的时间估算。

工具参数在执行整批调用前检查 JSON 语法及工具定义的参数格式。请求明确要求参数为一个 JSON 对象、包含全部必填字段并只做一次字符串转义；旧历史缺少字段不能作为新调用省略字段的依据。仅自动清除包裹完整对象的单个 JSON 代码围栏，以及完整对象后最多 8 个多余的 `}`（允许间隔 JSON 空白）；不修改对象内容、字符串或命令，不补缺失括号、字段或截断内容，不丢弃尾随文本、第二个对象或多余的 `]`。清理后仍须通过参数格式校验，执行和会话回放使用同一份有效参数；其他推理及提供方字段保持原样。语法错误、必填字段、类型或格式检查失败时，把未执行的整批调用以及错误分类、位置和具体修正提示反馈给模型，最多额外重新生成 2 次；一次最多列出 8 个格式问题。保留原有任务历史，不执行失败批次中的任何调用。工具参数诊断只记录请求 ID、工具、错误位置、脱敏格式错误和清理类型，不记录参数正文。流式回复已输出文字时也可修复，修复轮的文字在整批通过校验后才发送。超过次数仍失败时明确报错；输入预算、取消和超时继续生效，不增加输出上限。成功修复后的用量包含失败候选的模型用量。当前兼容接口未确认支持工具调用的 `strict` 约束，不强制发送该选项；普通文本的 JSON mode 不能替代工具参数校验。

流萤支持读取图片和文本：图片校验并缩放到最长边 1536 像素，文本最多读取前 8192 字节，每条消息最多读取前 8 个附件。截断、缺失和不支持的格式会明确告知模型；不会只根据文件名声称读过内容。图片原文件读取上限为 15 MiB；PDF、Word、Excel、音视频等需转换为文本或图片后提供。

Codex 原生生图结果保存为有会话权限校验的附件，在回复区直接展示并支持放大预览，刷新后仍可查看。完成事件和回合结束时恢复的图片按工具 ID 去重；图片数据不重复写入过程日志。没有内联图片数据时，仅从运行账号的 `$HOME/.codex/generated_images/<thread_id>/` 读取当前会话的图片，不使用 `CODEX_HOME`。生成失败或保存失败保留错误详情。升级前未接收的生图事件不会自动出现在历史消息中，原图仍保留在 Codex 生图目录，可从原始会话记录补回。

所有 Responses 请求均不发送 `max_output_tokens`，不设置应用层输出上限，使用模型服务自身的输出限制。输入预算默认查询实际使用的模型：先读取服务端模型信息；阿里云服务确认模型 ID 后，若接口缺少窗口字段，再查询该模型的官方文档。预算为上下文窗口预留查询到的模型最大输出空间，与模型最大输入限制取小值，再扣除 5% 安全余量（至少 64）；元数据未提供最大输出长度时只保留安全余量。模型元数据按服务地址、模型和密钥的 SHA-256 摘要隔离，不保存明文密钥。查询成功且有效的上下文窗口、最大输入/输出长度及来源持久化到 SQLite，后续优先复用，不自动过期，服务重启或模型接口/官方文档暂时不可用时仍可读取；输入预算始终按当前配置重新计算，不持久化显式兜底预算。内存成功缓存 1 小时，失败缓存 30 秒，并发查询合并；日志记录来源、限制及存储失败。`ASSISTANT_CONTEXT_TOKENS` 是可选输入预算上限，不能提高查询到的安全容量；仅在查询失败时作为显式兜底。没有隐含的 32768 默认值，查询失败且未配置兜底会明确报错。主 agent 和自建子 agent 均查询实际使用的模型，输入预算上限在 Agent 配置中按模型设置。占用量仍保守估算：文本按 UTF-8 字节计，每张缩放后图片预留 4096，包含工具定义；这不是模型 tokenizer 的精确 token 数，也不是计费 token 数。

扣除系统提示、工具定义和本轮用户输入后，过程记录占剩余空间的四分之三时触发 LLM 摘要，目标为剩余空间的一半（最多 8192 字节）。可以归纳全部工具结果，包括最近一次；保留目标、约束、关键发现、已完成操作和待办，缺少细节时优先通过 read_task_result 读取已有任务结果，不重复执行原工具。超长结果分块完整送给摘要模型，不直接截断；摘要在同一次运行中复用，新增过程记录继续累积到下次压缩。摘要失败时明确报错；系统提示、工具定义和本轮输入本身超限时仍需调整预算或减少输入。较大的引用对话快照先按同一策略生成摘要，再保存供后续使用。主模型用量包含运行期间的上下文摘要调用，子 Agent 用量随已结束的委派结果保存到 metadata，不作为完整计费账单。

Codex RPC 的期限覆盖写入和响应，未知执行会停止并回收连接；Claude 本地任务使用独立进程组，取消后确认进程退出再推进队列。

## 工具结果读取与回合完成

任务的完整结果保存在 SQLite，模型预览优先展示 `structuredContent`，去除与其相同的 MCP 文本副本；错误、图片和附件仍保留。截断结果附带 `result_bytes`、`readable_fields` 和 `read_result` 调用示例。通过 `run_tools` 提交宿主只读工具 `read_task_result`，按原结果的 JSON Pointer 选择字段；数组使用 `offset`、`limit` 分页（每页最多 128 条、4096 个序列化 UTF-8 字节）。响应包含 `data`、`total`、`next_offset`，条目完整返回，不截断条目；单条过大时选择更具体的字段。根 agent 只能读取当前用户和会话的结果，子 agent 还须属于同一回合及 handoff 作用域。读取不会重新执行原工具，不需要扫描目录或访问业务数据库。

Firefly 最终回复持久化并完成必要工具收尾后，提交回合状态并发送 `assistant_done`，不生成回合结束摘要，也不登记后台摘要任务。下一轮加载历史上下文，按输入预算需要进行压缩；引用回复创建分支时，超预算的继承上下文仍会摘要。旧版本已保存的 `context_summary` 继续兼容读取，不修改原始对话记录；升级会终止旧队列中待执行或运行中的后台摘要任务。

日志按 job_id 区分模型请求、工具执行及回合完成，记录耗时、模型用量、截断和参数重生成，不记录请求正文。

## 独立模块与定时任务

业务模块分别管理自己的页面、配置、数据和定时任务。模块包及运行依赖由模块作者提供；安装、启用和备份方式见 [外部模块文档](modules.md)。主项目的构建、测试和部署不依赖本机安装的业务模块。

对话清理默认启用：每天按 `APP_TIMEZONE` 的 00:00 永久删除最后更新时间 `updated_at` 达到 `CONVERSATION_RETENTION_DAYS` 的对话、关联消息、任务记录和附件文件。默认保留 30 天；设为 0 时不注册自动清理任务。发送消息、保存回复、重命名或更新工作目录状态会更新此时间；仅查看对话不会延长保留期。仍有排队或运行中生成任务的对话跳过，后续每天重查；实际删除前会在事务内重新检查最后更新时间和任务状态。侧边栏可将已结束的对话归档。列表初始只显示未归档对话，点击“查看归档对话”后在其后展开已归档对话，再通过“查看更多对话”分页加载，不单独设置归档 tab；两类列表分别分页，搜索重置为未归档列表，展开的归档记录支持实时更新。可在归档记录中查看或取消归档；归档会话只读，取消归档后可继续工作。归档与取消归档更新最后更新时间，仍遵循配置的未更新保留期限。曾移除归档状态的历史对话保持普通状态，可重新归档；旧归档 Codex 会话在首次继续工作时自动恢复底层会话。工作区目录沿用手动删除对话的行为，保留在磁盘上。任务需要服务在该时刻运行。

## Firefly agent 后台任务与取消入口

“侧栏左下角设置 → Agent 配置”可编辑 Firefly 主 agent 的提示词、模型、输入预算、执行期限和工具选择，并创建、启停、删除自己的子 agent。子 agent 包含稳定标识、名称、职责说明、提示词、模型引用与工具列表；主 agent 根据职责说明选择 `handoff_to_<标识>`，委派时传入目标、必要上下文和已有授权。子 agent 可继承主模型，也可选择独立模型配置；只获得自己勾选的工具。

配置持久化到本站 SQLite。首次初始化读取 `OPENAI_*`、`ASSISTANT_SYSTEM_PROMPT`、`ASSISTANT_CONTEXT_TOKENS` 和 `ASSISTANT_RUN_TIMEOUT_SECS`，保留旧实例已启用模块的直接工具；此后页面保存的配置为唯一来源，环境变量不覆盖已保存值。修改主提示词、模型、工具或子 agent 后，无需重启或重新编译；已有对话从下一轮使用新配置，正在执行的回答继续使用开始时的配置快照。缺少模型或工具的子 agent 本轮不注册，主助手会收到具体原因。停用模块仍按模块原有撤销机制处理在途工具调用。

工具列表包含核心工具和已启用的外部 MCP 模块工具；安装、启用新模块后可点击“刷新工具”并分配给不同 agent。页面支持 JSON 导入导出；导入仅更新草稿，保存后生效，导出不含模型 API Key。密钥存于本地数据库，API 读回仅展示是否已配置；同一模型配置和服务来源下留空保存保留原密钥，点击“清除密钥”删除。更换服务的协议、域名或端口时，未重新填写的旧密钥会自动清除，防止配置导入后把密钥发往其他服务。并发修改通过配置版本校验拒绝覆盖。模型服务需支持 Responses API；Codex、Claude 独立会话的 CLI 配置继续由各自管理。

每次子 agent 委派使用独立的持久化任务作用域：结束检查只等待本次委派的任务，退出或失败清理自己的附属任务，已转后台的任务继续执行。主回答停止时清理整个回答的附属任务。作用域保存在任务的 `scope_id`，复用现有任务事件、输出、取消和重启恢复机制。委派本身同步执行；后台命令完成不会自动重新唤醒子 agent 或主模型。

主 agent 可以通过 `run_tools` 提交多个工具任务，以 `wait_tools` 领取部分结果并继续推理，使用 `get_tasks` 查询状态及命令输出。`detach_tools` 将指定任务转入后台，回答结束、页面关闭和停止回答均不会终止这些任务；`cancel_tools` 或聊天区后台任务行的取消按钮可以取消任务及其子分支。取消不会撤销已产生的修改。

`run_tools.calls` 中每个任务必须提供 `title`，用用户的语言简短描述具体动作和对象（如“检查 RDP 会话状态”“运行项目测试”），作为任务标题展示。缺失、全为空白、超过 200 个字符或只填写工具名的标题会被拒绝；保存时去除首尾空白。历史任务标题保留原记录。

命令工具 `command` 通过 `run_tools` 调用，可以执行非交互的 Codex / Claude CLI、构建和测试；与已有 Codex / Claude 独立会话模式无关。`cwd` 限制在 `WORKSPACE_ROOT` 内，支持相对路径，只决定实际执行目录，不自动加锁；相同目录或仓库中的独立命令默认可并发。需要避免同时修改同一资源时，在 `command.arguments` 中显式传入相同的 `resource_key`（如 `repo:firefly`、`deploy:production`，1–255 个字符，无首尾空白）；互斥键跨会话生效，仅完全相同的键在执行期间串行，不做路径祖先匹配。不要以整个 workspace 作为通用锁。此互斥不覆盖外部程序或已有独立会话。命令运行于服务进程的权限和环境中，应仅执行用户授权的操作，不应 daemonize 或主动脱离进程组。

分配了 `command` 工具的 agent 每轮追加文件搜索指令，已有对话同样生效：文件内容搜索优先使用 `rg`，文件名定位使用 `rg --files -g`；先确定项目，再设置 `cwd` 并搜索相关目录，逐步扩大范围，默认遵守忽略规则。只有确认 `rg` 不可用时才回退到限定范围的 `grep`；`rg` 退出码 1 表示没有匹配，不触发回退。

```json
{
  "calls": [{
    "tool": "command",
    "title": "运行项目测试",
    "arguments": {"command": "npm test", "cwd": "project-a"},
    "execution_timeout_secs": 7200
  }],
  "yield_when": "any",
  "wait_timeout_secs": 30
}
```

后台工具任务不设执行名额上限；可安全并行且显式互斥键不冲突的任务直接启动，资源互斥与工具串行规则仍会使任务排队。排队不设超时。普通工具默认执行期限为 300 秒，命令默认 7200 秒，从实际启动开始计时；可按调用覆盖，默认允许最长 604800 秒。`wait_timeout_secs` 只结束本次等待，不终止任务。配置项见 `.env.example` 的 `ASSISTANT_TASK_*`、`ASSISTANT_COMMAND_*`、`ASSISTANT_TOOL_TIMEOUT_SECS` 和 `ASSISTANT_RUN_TIMEOUT_SECS`。

任务、父子关系、输出与结果保存在 SQLite。前端通过持久化事件游标和长轮询同步当前回答关联的后台任务状态；聊天区只在当前回答存在运行中后台任务时显示一行“后台任务 N”和取消入口，不展示任务树或逐层明细。后台任务完成后只更新状态，不自动再次调用模型。命令输出默认最多保存 16 MiB；模型读取最近的输出片段，任务详情接口可按任务 ID 加载输入、结果和最近 100,000 字符的输出；任务列表与实时事件只返回状态概况。任务结束前可随时查询输出，完整长结果应写入工作目录文件。

任务标题使用调用者传入的 `title`；普通工具任务显示实际工具名称，委派任务显示目标 agent 名称，不维护特定业务的名称映射。父子关系由后端任务记录维护，供状态查询和按分支取消使用。

子 agent 收起时同时隐藏其全部执行步骤与详情；右侧保留工作摘要，优先使用返回报告中的 `summary`，执行中显示委派目标。摘要最多 160 字，不加载完整工具详情。子 agent 结束后计时固定；服务重启中断的旧委派会同步为“结果未知”，使用恢复记录的时间停止计时，主 agent 续跑不会重新激活旧委派。

`get_tasks({})` 默认只查询运行中的任务、本轮尚未领取的结果及未确认的 `unknown`，每页 32 条、最多 64 条；本轮未领取的完成结果优先返回，领取后再次空查询可处理下一批。已领取的历史结果不再自动返回。查看具体任务时指定 `task_ids`；历史查询需显式设置 `include_history: true`，用返回的 `next_offset` 翻页。概况默认不读取输出，必要的本轮结果仍带有界预览；显式 ID 查询默认读取输出，也可用 `include_output` 控制。每次结果与输出预览共用 32 KiB 的内容预算，截断会明确标注，完整内容仍在任务详情或结果文件中。旧对话中超大的任务快照载入模型上下文时也会缩减，数据库原记录保留。

启动提示仅列出需关注任务的有限概况，不要求每轮重读全部历史。服务重启保留已领取结果的状态，仅未领取结果需要补领；收尾提示提供本轮未转入后台的具体阻塞任务 ID，不要求清理旧任务或取消仍供用户扫码、确认的后台会话。

重启保留已完成结果，排队的后台任务继续排队；运行中任务标记结果未知，不自动重跑。`unknown` 表示结果无法确定，不再永久占用互斥资源；再次执行前仍需核实实际状态。启动时将旧版自动生成的 cwd/仓库锁替换为参数中显式声明的互斥键，未声明则清空，任务历史和执行目录保留。此实现不保证本地进程跨服务重启存活。

Firefly 通过 crates.io 依赖 `glow-agent = 0.1.0`，保留 `g` 依赖别名以兼容现有代码。版本在 `Cargo.toml` 中固定，`Cargo.lock` 记录注册表来源和校验和。升级运行时前，先确认 [Glow](https://github.com/42tr/g) 已发布配套版本，再更新依赖和锁文件，运行 Rust 检查。后台任务行浏览器测试：启动 Vite 端口 5193 后执行 `python3 frontend/tests/e2e/test_background_task_bar_ui.py`。
