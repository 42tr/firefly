# Agent 记忆人工确认：设计方案

## 目标

Agent 完成一轮对话后，可以识别出值得长期保存的信息，但不再直接写入长期记忆。系统先把候选记忆放进“长期记忆”模块的“待确认”区域，用户打开模块后可以逐条查看、修改、取消选择，最后一次性确认保存。

核心原则是：**候选记忆和已生效记忆必须有明显的状态差异，用户的确认动作才是写入的唯一入口。**

## 推荐流程

1. 对话完成后，后台记忆审查器生成 0–8 条候选记忆。
2. 没有候选时不显示任何提示，保持当前对话不被打扰。
3. 有候选时，长期记忆模块入口显示“待确认 N 条”徽标。用户打开模块后，顶部先展示“待确认”区域，再展示“已生效”区域；对话内容本身不增加任何卡片或提示。
4. 每条候选默认选中，显示“新增”或“更新”、标题、内容和“建议原因”。用户可以：
   - 取消这一条；
   - 展开编辑标题和内容；
   - 展开“建议原因”查看来自本轮对话的证据；
   - 直接忽略本批候选。
5. 点击“确认保存 N 条”后，只提交当前选中的内容。保存成功后，候选从“待确认”区域移动到“已生效”区域，并显示短暂成功提示。
6. 保存失败时保留所有编辑内容，显示错误原因和“重试保存”，不丢失用户修改。

## 页面结构

### 长期记忆模块

- 模块标题：`长期记忆`
- 顶部说明：`Agent 建议保存的内容会先放在这里，只有确认后才会生效。`
- 分区顺序：`待确认（N）` → `已生效（N）`
- 待确认区空态：`暂无待确认内容`
- 已生效区继续沿用当前记忆列表，增加启用/停用、编辑和删除操作
- 候选行：选择框 + 状态标签 + 标题 + 内容摘要 + 编辑按钮
- 编辑态：标题输入框、内容文本框、证据折叠区、`完成编辑`
- 操作区：`暂不保存`、`确认保存 N 条`

待确认行使用暖黄色的“待确认”标签，和已生效记忆的“Agent 添加 / 手动添加”来源标签区分。选择框放在每条候选最左侧，编辑按钮放在右侧，点击区域不与选择框重叠。移动端候选行改成上下结构，批量操作区固定在待确认区底部。

### 顶部提示

在“长期记忆”入口或更多菜单项旁显示非模态徽标：`待确认 2 条`。点击后打开记忆模块并聚焦“待确认”标题；确认或忽略后徽标消失。徽标只负责找回入口，不承担确认操作。

### 已生效记忆管理

现有“长期记忆”弹窗继续保留，用于查看、启用/停用、编辑和删除已经生效的记忆。提示文案改为：

> Firefly 只会使用你确认保存的记忆。你可以在这里管理已生效的内容。

## 状态与反馈

| 状态 | 页面表现 | 用户动作 |
| --- | --- | --- |
| 审查中 | 记忆模块显示低干扰加载行 `正在整理可选记忆…` | 无需操作 |
| 待确认 | 记忆模块顶部的 `待确认` 分区 + 入口徽标 | 查看、编辑、取消、确认 |
| 编辑中 | 当前候选展开表单，其他候选保持可见 | 完成编辑或取消编辑 |
| 部分选择 | 主按钮实时显示 `确认保存 N 条` | 继续选择或保存 |
| 保存中 | 主按钮显示 `保存中…`，表单暂时锁定 | 等待结果 |
| 保存成功 | 候选移动到 `已生效`，显示绿色提示 `已保存 N 条记忆` | 继续管理或关闭模块 |
| 用户忽略 | 待确认分区收起为 `本次未保存任何记忆`，不写入数据库 | 可关闭提示 |
| 保存失败 | 候选保留在待确认分区，显示错误信息和 `重试保存` | 重试或忽略 |

## 关键文案

- “待确认”比“自动记忆”更准确，直接表达当前还未写入。
- 主按钮使用“确认保存”，避免“提交”“应用”等不明确的词。
- 证据标签使用“建议原因”，展开后说明“来自本轮对话的原文片段”，让用户知道 Agent 为什么提出这条记忆。
- 不使用“永久保存”；记忆仍可被用户停用、编辑或删除。

## 开发落点（本轮只做设计，不实施）

当前后端在 `run_review_worker` 中生成候选后立即调用 `apply_reviewed_memories_for_turn`，所以要实现人工确认，需要把“生成候选”和“写入记忆”拆开：

1. 记忆审查任务生成候选并持久化为 `pending`，不写入 `assistant_memories`。
2. 增加按会话读取待确认候选的接口，以及确认/忽略接口；确认接口沿用现有校验、去重、快照校验和 evidence 记录。
3. 通过现有 realtime 订阅或会话刷新通知前端候选已生成，前端只在当前会话展示。
4. 用户编辑后的标题、内容和选择状态只保存在待确认任务中，确认时一次性提交。
5. 候选任务需要有过期、会话删除、重复点击和并发编辑保护；候选记录确认后变为 `completed`，忽略后变为 `dismissed`。

实现上保留 `assistant_memory_jobs` 的 `completed` 表示“审查生成完成”，另由候选表维护 `pending → completed / dismissed`。这样不会把待确认内容写进 `assistant_memories`，也兼容现有审查队列的恢复逻辑。

## 验收标准

- Agent 完成回复后，任何候选都不会自动出现在“长期记忆”列表中。
- 用户可以只保存其中一条，也可以编辑后再保存。
- 刷新页面或切换会话不会丢失未处理候选。
- 重复点击确认不会产生重复记忆。
- 保存失败时用户编辑内容仍在，且可以重试。
- 桌面端和移动端都能在 3 秒内理解“这几条还没保存，需要我确认”。
